# AI 漫画长图生产工具 · 最终设计方案 v1

> 基于：两份 GPT 调研文档 + spike 四轮实测验证（spike/）+ references/ 七个仓库的代码级调研。
> 状态：待评审。评审通过后按第五节的阶段分期实施。

---

## 一、产品定义（一句话）

输入一个主题，AI 自动完成故事、人物、场景绘制，程序叠加气泡/文字/手机屏幕特写框，输出 1080 宽公众号长图 + 可编辑 PPTX；全程可人工介入，任意一格、任意一层可单独重跑。

## 二、总体架构

**不 fork 任何仓库。** 我们自己的代码库，按需从 references/ 抄文件/抄思路（全部为 MIT/Apache-2.0，合规无障碍）。

**技术选型定论：**

| 层 | 选型 | 理由 |
|---|---|---|
| 写故事 | gpt-5.6-sol（中转站，OpenAI 兼容） | 已实测，便宜 |
| 画图 | gpt-image-2（同上，generate + edits 参考图） | 已实测，人物/道具一致性过关，中文写字过关 |
| 后端 | FastAPI + Pydantic，JSON 文件持久化 | spike 已验证；lumenx 同款模式；暂不需要数据库 |
| 抠图 | rembg 库（`birefnet-general`，CPU 即可） | MIT；进程内调用零运维；**显式指定模型，不用默认的 bria（商用受限）** |
| 气泡渲染（后端） | 搬 manga-studio `bubbles.py`（纯 PIL） | 智能定位（扫细节少区域）现成；需改中文断行 |
| 气泡排版（前端） | vendor pretext-comic 的 `src/core` + `src/shapes` | 形状感知换行 + 自动字号；需改 CJK 分词（约 15 行） |
| 画布编辑器 | konva + react-konva（npm 安装，不用 references 源码） | Stage/Layer/Image/Label/Transformer 全覆盖 |
| PPTX 导出 | pptxgenjs（npm，浏览器内导出） | 对象全部原生可编辑；每格一页（长页有 56 英寸硬限制，放弃） |
| 前端框架 | Vite + React | 主流、和 react-konva/pptxgenjs 同栈 |

## 三、核心数据模型（三张表的正式版）

沿用 `schemas/` 三张表，从调研中补四个机制：

1. **资产版本池**（抄 AIComicBuilder `shotAssets`）：每次重跑生成新版本 `v1/v2/v3...`，旧版不删，`is_active` 指向当前版，可一键回滚。落盘为 `versions/` 目录 + scene JSON 里的版本指针。
2. **图池 + 选中**（抄 lumenx `ImageAsset/ImageVariant`）：单格重跑 N 次、人工挑一张，最多保留 10 个变体。
3. **stale 传播**（抄 AIComicBuilder）：人物标准照重画 → 所有引用该人物的场景自动标 `stale`，提示需要重跑。
4. **气泡几何回写**（来自 pretext-comic 调研的关键决策）：**前端编辑器算好每行文字坐标和字号，写回 scene JSON；后端拼长图时只做"按行画字"的哑渲染**，不再自己换行——这样"编辑器里看到的 = 最终长图得到的"，两端不会打架。

## 五、分期实施计划

> 原则：每期结束都有**能跑、能验收**的东西，不留半截工程。

### 第 1 期：后端核心引擎（纯 Python，无 UI）
把 spike 四个脚本重构成正式引擎，项目目录结构落盘，三张表驱动全流程。
- 验收：命令行一个命令从主题跑出长图；删掉某一格产物重跑只重画那一格；重跑产生 v2 不覆盖 v1。
- 带上已知的两个修正：屏幕素材提示词加"只画屏幕内容不要手机外壳"；审核误拦自动降级重试。

### 第 2 期：HTTP API（FastAPI）
项目 CRUD、`POST /projects/{id}/generate {action}` 单入口分发（story/characters/scenes/screens/compose/rerun_scene）、后台任务 + 轮询、图片静态服务。
- 验收：用 curl/Postman 能走完整个流程；单格重跑、版本回滚都有接口。

### 第 3 期：前端基础（React，无画布）
项目列表页 + 项目工作台：故事表查看与编辑（对话、caption 直接改）、逐格预览、风格选择下拉框、"重跑这一格"按钮、长图预览与下载。
- 验收：不碰命令行，全程网页操作产出一部长图。

### 第 4 期：画布编辑器（Konva）
每格一个画布：拖气泡（尾巴跟随）、双击改字、拖/缩放手机屏幕特写框、字号调节；保存写回 scene JSON；后端按回写坐标哑渲染。
- 验收：气泡能从错误的人头上拖到正确的人旁边，长图随之更新。
- 集成 pretext-comic 的形状感知排版（椭圆/思考/呼喊气泡 + 自动字号）。

### 第 5 期：交付与收尾
PPTX 导出（每格一页，文字可编辑）、字体资产管理（授权登记表）、审核状态流（draft→review→approved）、人物透明图层（rembg 抠图，支持"只要人物不要背景"模式）。
- 验收：导出 PPTX 在 PowerPoint/WPS 里可拖可改；整部长图可标记审核通过并归档。

## 六、已知风险登记

| 风险 | 应对 |
|---|---|
| 中转站审核误拦个别提示词（国风已遇到） | 图像服务层做降级：去掉参考图重试 / 改述提示词 |
| 前后端文字排版不一致 | 前端算坐标、后端哑渲染（第三节第 4 点） |
| PPTX 里气泡尾巴方向不可编程 | 圆角矩形 + 独立小三角形组合实现 |
| rembg 模型首次需联网下载（约 900MB） | 部署时预下载打包 |
| 编辑器是最大工作量 | 放在第 4 期，前 3 期先让流程可用 |
