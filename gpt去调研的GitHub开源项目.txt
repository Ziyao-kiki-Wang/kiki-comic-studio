我把这一轮 GitHub 调研做下来以后，结论比我原先预想的要好：**我们不需要从零造这套系统。**

我目前没有找到一个 repo 能完整覆盖你要求的：

> 主题 → 文稿/分镜 → Character Bible → 跨图人物一致 → 分层人物/背景 → 气泡/字体 → 长图 → 可编辑 PPTX → 审核 → Component-level rerun

但已经找到几个项目分别把其中最难的部分做掉了。尤其是 **LumenX + manga-studio + Konva + PptxGenJS** 这一组合，基本可以搭出我们需要的产品。

# 1. 最值得看的：Alibaba LumenX

[GitHub：alibaba/lumenx](https://github.com/alibaba/lumenx?utm_source=chatgpt.com)

这个是我这一轮调研里，**最适合作为“大系统骨架”参考甚至直接 fork 的项目**。

它目前已经有：

```text
Script
 ↓
角色 / 场景 / 道具提取
 ↓
Art Direction
 ↓
角色资产
 ↓
Storyboard
 ↓
分镜图
 ↓
Video
 ↓
Assembly
```

也就是说，你前面定义的：

* Project
* Story
* Character
* Scene
* Asset
* Storyboard
* Generation Task

这些数据模型，它基本都已经有了。

更关键的是它不是个简单 Demo。目前 GitHub 仓库有数百次 commit，并且还在持续开发；整个项目是 MIT License。([GitHub][1])

### 和你的需求重合到什么程度？

非常高。

它的剧本阶段已经支持 LLM 自动提取：

```text
角色
场景
道具
结构化分镜
```

还存在统一 Art Direction，用来控制整个作品的视觉风格。([GitHub][2])

尤其值得注意的是它的**人物资产流程**：

> 先生成无背景人物全身照，再基于该人物生成三视图和头像，把这些作为后续所有画面的参考资产。

这基本就是我们上一轮定义的：

```text
Character Bible
+
Character Reference Sheet
```

而且之后分镜生成时，可以选择：

```text
Character Reference
Scene Reference
Prop Reference
```

参与图像生成。([GitHub][2])

甚至 README 明确写过：

> 拖拽式分镜编辑器，组合人物、背景与特效。

所以它已经开始向我们说的：

```text
Scene Graph
```

这个方向走了。([GitHub][2])

# 2. 它为什么还不能直接解决你的问题？

因为 LumenX 的目标是：

> **AI 漫剧 / 视频**

而我们是：

> **静态公众号条漫 / 长图**

所以它越到后半段，越开始偏离我们：

```text
我们                     LumenX

Storyboard               Storyboard
    ↓                        ↓
Illustration              Key Frame
    ↓                        ↓
Bubble/Text               Video
    ↓                        ↓
Long Image                Audio
    ↓                        ↓
PPTX                      FFmpeg
```

而且 LumenX 自己在设计文档里也明确说，它不是 Photoshop/Figma 那种重型专业编辑器。([GitHub][3])

所以我的判断是：

> **LumenX 非常适合抄/复用“前 60%”，不适合拿它的后 40% 硬改。**

# 3. 第二个项目反而和我们静态漫画特别像：manga-studio

[GitHub：ahmet360/manga-studio](https://github.com/ahmet360/manga-studio?utm_source=chatgpt.com)

这个项目的 star/工程成熟度远不如 LumenX，而且目前仓库历史很短，所以**我不会建议把整个产品建立在它上面**。

但是：

> 它的生产架构是这一轮里面**最像你需求的**。

它已经明确实现：

```text
Script
 ↓
Panel rendering
 ↓
Background plate
+
Character A cutout
+
Character B cutout
 ↓
Layer composition
 ↓
Speech bubbles
 ↓
Page assembly
```

并且它明确写的是：

> 多人物场景生成背景板 + 每个人物独立透明 cutout，像 Photoshop layer 一样进行 compositing；每一层都可以独立导出、替换或者重新生成。([GitHub][4])

这句话非常关键。

因为这就是我们上一轮说的：

```text
Component-level regeneration
```

比如：

```text
Scene 04

background.png
character_A.png
character_B.png
bubble_01
bubble_02
caption
```

审核说：

> B 的动作不好。

只：

```text
regenerate(character_B)
```

就行。

**其他东西都不用动。**

# 11. 人物一致性：这一块已经有大量现成方案

这里我们实际上不用自己研究算法。

比较经典的：

### StoryDiffusion

[GitHub：HVision-NKU/StoryDiffusion](https://github.com/HVision-NKU/StoryDiffusion?utm_source=chatgpt.com)

就是专门解决：

```text
Scene 1 → Alice
Scene 2 → Alice
Scene 3 → Alice
...
```

跨长序列人物一致性。

它通过 Consistent Self-Attention 做 character-consistent sequence generation，而且官方 Demo 本身就是 Comic Generation。([GitHub][10])

不过它主要还是 SDXL 时代方案，而且推荐二十多 GB GPU，所以我不会把它作为我们 2026 年 MVP 的第一选择。([GitHub][10])

# 13. 真人 → 漫画人物也不用自己研究

已经有成熟模块，例如：

### IP-Adapter

[GitHub：Tencent IP-Adapter](https://github.com/tencent-ailab/IP-Adapter?utm_source=chatgpt.com)

它可以把 reference image 作为 image prompt，而且能和 ControlNet 等结构控制一起使用，Apache-2.0。([GitHub][13])

以及：

### PhotoMaker

[GitHub：TencentARC/PhotoMaker](https://github.com/TencentARC/PhotoMaker?utm_source=chatgpt.com)

专门做 identity customization，也是 Apache-2.0 代码。([GitHub][14])

InstantID 也可以做单张人脸 identity preserving，不过它存在一个商业产品需要注意的 license 坑：

> InstantID 代码本身是 Apache-2.0，但其 InsightFace 依赖/部分 checkpoint 的许可不等同于无限制商业使用。([GitHub][15])

所以如果这是以后会商业部署的东西，我反而不会把 InstantID 放第一优先级。

# 23. 只有三块我认为我们真的需要自己写

其实没有想象得多。

### A. 我们自己的 `Scene Schema`

这是核心 IP。

例如：

```json
{
  "scene_id": "s03",

  "background": {
    "asset_id": "bank_hall_01"
  },

  "characters": [
    {
      "character_id": "staff_01",
      "asset_id": "staff_pose_05",
      "x": 0.62,
      "y": 0.31,
      "scale": 0.84
    }
  ],

  "bubbles": [
    {
      "speaker": "staff_01",
      "text": "请先不要转账。",
      "x": 0.1,
      "y": 0.05
    }
  ]
}
```

这个必须自己控制。

```text

 ↓

 ↓
Caption
 ↓
Scene 3
 ...
```

这一层需要自己写。

不过技术上并不难。

# 25. 所以我现在的结论非常明确

**不要自己从零写一个 AI Comic Pipeline。**

也**不要找一个项目 fork 下来以后把所有东西都塞进去。**

最合理的是：

> **LumenX 做骨架 + manga-studio 做静态分层生产逻辑 + Konva 做编辑器 + PptxGenJS 做交付格式。**

然后：

```text
AI-Comic-Generator
AIComicBuilder
```

拿来抄它们的数据结构和 UX。

这样我们实际上真正需要原创开发的核心，已经缩成：

```text
1. 我们自己的 Storyboard Schema
2. Scene Graph Schema
3. Long Image Layout Engine
4. Review / Revision logic
5. PPTX mapping
```

这五件事。

而且我现在已经可以比较确定地说，**最难的“人物一致性”“分层生成”“气泡”“编辑器”“PPTX”都不用从算法层面重新造轮子。**

下一步如果继续往 coding 推，我建议直接进入更具体的一步：我可以把上面这些 repo **进一步拆到“具体文件/类/API”级别**，比如明确告诉你：

> LumenX 哪几个目录值得直接拿；manga-studio 的哪几个 `.py` 可以复用；Konva 应该怎么定义我们的 `SceneNode`；PptxGenJS 怎么从同一个 JSON 输出 PPTX。

做到那一步以后，我们基本就能形成一份真正可以交给 Codex/Claude Code 开工的 **Architecture Spec + repo scaffold** 了。
